O que é Modelação de Dados?

Modelar dados é o processo de organizar as informações de um sistema antes de criar o banco de dados de verdade. Passamos por três níveis de abstração, do mais próximo do "mundo real" ao mais próximo do computador:

Nível O que representa Exemplo prático
Conceitual Visão geral do negócio, sem detalhes técnicos. Foca em entidades e relacionamentos. "Um Aluno se matricula em uma Turma."
Lógico Define atributos, tipos de dado e chaves — ainda independe do SGBD usado. ALUNO(id, nome, email) relacionado com TURMA(id, nome)
Físico Implementação real: nomes de colunas, tipos exatos do SGBD, índices, constraints. CREATE TABLE aluno (id INT PRIMARY KEY, nome VARCHAR(100));
Nível 1

Modelo Conceitual

É a etapa da "conversa com o cliente". Aqui identificamos:

  • Entidades — os "substantivos" do sistema (Aluno, Curso, Professor)
  • Atributos — as características de cada entidade (nome, idade)
  • Relacionamentos — como as entidades se conectam (Aluno cursa Disciplina)

Nesta fase ainda não nos preocupamos com tipos de dado, SGBD ou performance — só com o significado das informações.

Nível 2

Modelo Lógico

Traduzimos as entidades do modelo conceitual em tabelas, com colunas, tipos de dado genéricos e as chaves que vão ligar as tabelas entre si.

TabelaColunaTipoObservação
ALUNOid_alunoInteiroChave primária (PK)
nomeTextoObrigatório
id_turmaInteiroChave estrangeira (FK) → TURMA
Nível 3

Modelo Físico

É a implementação final, escrita na linguagem do SGBD escolhido (MySQL, SQL Server, PostgreSQL...). Cada SGBD tem pequenas diferenças de sintaxe — veja a página de Comandos SQL para comparar MySQL e SQL Server lado a lado. 

CREATE TABLE aluno (
    id_aluno INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    id_turma INT,
    FOREIGN KEY (id_turma) REFERENCES turma(id_turma)
);
